## Confirmed defect in this work unit

`core.permissions.has_organization_role()` previously checked authentication, membership, organization, and role but did not reject an inactive user account before matching active membership. This could authorize a caller that reached a role-protected operation through an indirect call even though Django's normal login flow rejects inactive accounts. The predicate now rejects unauthenticated/inactive users before the existing superuser bypass. Tests cover an inactive ordinary user with an active membership and an inactive superuser; the prior predicate would have authorized the ordinary user's matching role and the inactive superuser.
